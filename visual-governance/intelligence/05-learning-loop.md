# 🔁 الوحدة 5 — حلقة التعلّم المستمر
> النظام يتعلّم من بياناته الحقيقية ويقترح تحسينات مُصدَّرة. تشغّلها مراجعة أسبوعية + ربعية.

## المدخلات (Inputs)
- **أداء المحتوى:** تفاعل، CTR، زمن البقاء/الاحتفاظ (من GSC/GA4/يوتيوب).
- **تغذية المستخدمين:** تعليقات، شكاوى، إشارات الجمهور.
- **تغذية المحرّرين:** ملاحظات الفريق على القواعد والبرومبتات.
- **نجاح/فشل توليد الـAI:** KPI-4 + أنماط الفشل.
- **أنماط فشل الامتثال:** أي محور يرسب أكثر (من سجلّ الامتثال).

## المعالجة (Process)
1. **رصد الأنماط المتكرّرة:** ما السبب الأكثر تكراراً للرفض؟ أي برومبت يفشل دوماً؟ أي نوع محتوى يتعثّر؟
2. **عزل الضعف:** قاعدة غامضة؟ برومبت ضعيف؟ SOP ناقص؟ معيار غير واقعي؟
3. **صياغة فرضية تحسين** مدعومة برقم (مثال: «برومبت الصحة ينتج يدين مشوّهتين 40% → أضف negative prompt محدّد»).

## المخرجات (Outputs)
- **توصيات تحسين مهيكلة:** المشكلة + الدليل (رقم) + التغيير المقترح + الوحدة المتأثّرة.
- **تحديثات مُصدَّرة** للبرومبتات/الـSOPs/المعايير عبر نموذج الإصدار (الوحدة 4) مع فترة ظلّ.
- بند في `quality-log.md` + تشديد `content-standards.md`/الملف البصري المعني.

## الإيقاع
| الدورة | النطاق |
|--------|--------|
| **أسبوعي** | أعلى 3 أسباب رفض + أضعف برومبت → إصلاح سريع (PATCH/MINOR). |
| **شهري** | اتجاهات KPIs + أداء المحتوى → تحسينات أكبر. |
| **ربعي** | مراجعة المعايير ككل: ما يُرفع باره؟ ما يُهلَك؟ |

## الحلقة المغلقة
بيانات → نمط → فرضية → تحديث مُصدَّر (بظلّ) → قياس الأثر → تثبيت أو تراجع. **كل تحسين يُقاس أثره** قبل تثبيته.

> الهدف: نظام كل أسبوع أذكى من سابقه، وبياناته هي معلّمه.
