# 🏭 خطة تنفيذ كلود شيب — كل المقالات (59 تاسك)
> من: عامر (مدير الجودة). الإشراف والمراجعة: عامر مباشرةً بعد كل تاسك. اليوم: **كتابة فقط**.
> السبب: أدسنس رفض الموقع «Low value content». الهدف: رفع عمق وقيمة كل مقال.

## ⛔ محاذير حاكمة (خطّ أحمر — اقرأها قبل أي تاسك)
1. **لا تقترب من التصميم إطلاقاً.** ممنوع فتح/تعديل أي HTML أو CSS أو JS أو قالب أو هيدر/فوتر أو Schema أو صور أو روابط برمجية أو classes أو أي وسم.
2. **مخرجك نصّ فقط** (Markdown/نص عادي). **لا تكتب أي HTML/وسوم/JSON-LD.**
3. **لا تعدّل أسماء الملفات ولا أماكنها ولا أي إعداد تقني.** كل ما هو تقني = عامر حصراً (الحقن في الصفحة، Schema، الصور، الروابط).
4. لو شككت «نص أم تقني؟» → اتركه لعامر.
> القاعدة: **أنت تكتب الكلمات، عامر يبنّيها في الصفحة.** هكذا لا ينكسر أي تصميم ولا نضيّع وقتاً.

## 🔁 بروتوكول التنفيذ
- نفّذ التاسكات **بالترتيب** من تاسك 01 حتى 59، **دون توقف**.
- **بين كل تاسك والذي يليه: توقّف 5 دقائق**، وخلال هذه الوقفة **افتح حقل `amer_review` للتاسك الذي أنهيته**:
  - **معتمد** → انتقل مباشرةً للتاسك التالي.
  - **تطوير (محدّد)** → طبّق ملاحظات عامر على مسوّدات ذلك التاسك أولاً، حدّث `chef_status` بأنك طبّقت، ثم انتقل للتالي.
  - **رفض** → أعد كتابة المسوّدات حسب السبب، حدّث `chef_status`، ثم انتقل للتالي.
- **قبل أن تسلّم أي تاسك، مرّر مسوّداتك على البوابة ذاتياً** (كلمات≥1300، صفر شرطات، FAQ، إخلاء للحساس، مصادر) لتقليل دوران المراجعة.
- **تاسك واحد في كل دورة** (لا تسلّم عدة تاسكات للمراجعة دفعة). **تجميد عند الرفض:** لا تفتح التاسك التالي قبل إغلاق الحالي (اعتماد أو تطبيق تطوير/إعادة).
> الحوكمة الكاملة في `operating-system/manager-charter-adsense.md` (ميثاق حاكم). والتقدّم في `operating-system/reports/ready-to-build.md`.
- كل تاسك = **موضوعان** (كل موضوع = نسخة عربية + إنجليزية). الملفات المعنية مذكورة داخل بطاقة التاسك.
- عند إنهاء تاسك: **اكتب «✅ تم التنفيذ» في حقل `chef_status` للبطاقة** + ألصق النص الناتج (أو مساره) + عدد كلمات كل نسخة + المصادر. **لا ترجع لجوست.** عامر يراجع مباشرةً.
- عامر سيضع نتيجته في `amer_review`: **اعتماد / تطوير (ماذا) / رفض (لماذا)**. إن طُلب تطوير، عالجه ثم تابع.

## ✅ معايير كل مقال (مطابقة `content-standards.md`)
- **1300–1800 كلمة** لكل لغة، بلا حشو. الفقرة الأولى تجيب السؤال + خطّاف أول سطر.
- **6–8 عناوين H2** + **جدول/قائمة خطوات** واحدة على الأقل (مثال ملموس بأرقام محلية).
- **FAQ: 4–6 أسئلة** بإجابات 2–4 جُمل.
- **إخلاء مسؤولية** للأقسام الحساسة (صحة/مالية/شرعية): «معلومات عامة، ليست استشارة/فتوى؛ راجع المختص/أهل العلم».
- **لا رقم/نسبة بلا مصدر موثوق محقّق يُذكر صراحةً.** ممنوع اختلاق دراسات/أرقام.
- **صفر شرطات طويلة (—)**، **صفر كليشيهات AI** («في الختام»، «علاوة على ذلك»، «في عالمنا السريع»…).
- **أسلوب آدمي** متنوّع الجمل، أمثلة خليجية. **الإنجليزية native** (تكيّفية لا حرفية، نفس العمق).
- خلاصة عملية + **CTA لأداة** + اقتراح **3 روابط داخلية** كنص.
